# SWIM PACE

水泳の「50m × 14 / 4H1E3H1E2H1E1H1E」用の目標タイム共有アプリ。

## 機能

- Fr・Br・Fly・Baごとにベストタイム・1HのAを保存
- A＝理想、B＝A＋1秒、C＝A＋2秒
- 2H・3H・4Hは1Hから＋1秒・＋2秒・＋3秒
- Firebase AuthenticationのGoogleログインで管理者のみ登録・更新
- Firestoreの同じデータを閲覧者にリアルタイムで反映
- 閲覧者はログイン不要。同じURLを共有
- 旧版の端末保存データを一覧確認・バックアップして移行
- 同時更新の競合を検知し、古い内容での上書きを防止
- スマートフォン向け編集画面とホーム画面追加用設定

## Firebaseの設定

FirebaseのSpark（無料）プランで、Firestore StandardのデフォルトDBとGoogle認証を用意します。使用量には無料枠の上限があります。

1. FirebaseコンソールでWebアプリを登録します。Google Analyticsは本アプリでは使用しません。
2. AuthenticationでGoogleプロバイダーを有効にし、配信先ドメインを承認済みドメインに追加します。
3. `firebase-config.example.js`を`firebase-config.js`へコピーし、Web設定・管理者メールアドレスを入力します。サービスアカウント秘密鍵は不要です。
4. `firestore.rules`の`admin@example.invalid`を同じ管理者メールへ変更して、Firestoreへデプロイします。実際の管理者メールを含む変更は公開リポジトリにコミットしないでください。
5. HTTPSの静的ホスティングへ配信します。依存パッケージのインストールやビルドは不要です。Firebase SDKはGoogle公式CDNから取得します。
6. 管理者がGoogleでログインし、「端末データを確認して移行」から一覧を確認して保存します。以降の更新は同じURLへ反映されます。

ローカル確認は `python -m http.server 8000`。Googleログインを使う場合はlocalhostも認証ドメインに登録してください。設定のないGitHub版は接続エラーを表示し、登録・更新を許可しません。

## 移行

旧版を使っていた端末・ブラウザから実行してください。端末の既存データは読み取り元として保持し、Firebaseへの保存成功前には変更しません。確認画面では、重複する選手の同じ泳ぎ方について端末の値を優先します。共有済みの別の泳ぎ方は保持します。初期データによる共有済みの値の上書きは行いません。

## 個人情報とアクセス

このリポジトリには選手情報、実際のFirebase設定、管理者メール、稼働中アプリのURLを含めません。初期登録データは空です。既存アプリの個人情報を含むGit履歴も引き継いでいません。

デプロイ後は、共有URLを知る人が選手情報をログインなしで閲覧できます。リンクの転送先も閲覧可能です。閲覧者を特定の部員だけに制限する機能はありません。Firestoreルールは公開対象の1ドキュメントへのgetのみ許可し、書き込みはメール確認済みの指定Google管理者に限定します。UIのボタン非表示に加えて、バックエンドでも権限を検証します。

旧版のデータ入りURL、バックアップ、選手画面の画像、実データをIssueやコードに貼らないでください。`.gitignore`は個人情報の直接記載を防げないため、差分を確認してください。Firestoreへのアクセス制限は、必ずデプロイ時に管理者設定と一致させてください。

## テスト

Node.jsで `node --test tests/app.test.cjs` を実行します。移行・権限表示・保存失敗・共有URLの挙動を確認します。実際のFirebaseルール・認証・配信ドメインは別途本番接続で確認してください。

## メニューと表テンプレート

メニューはプルダウンで選択します。管理者の「メニューを作成」から、内容入力 → 行・列テンプレート → 適用する選手の選択、の順で登録します。各選手の各泳ぎ方に空の表を生成します。行は最大6、列は最大12、メニューは最大30件です。

「列・テンプレートを編集」で項目名の変更や追加を行えます。項目の内部IDを保持するため、名前変更や列追加で既存の入力値を上書きしません。削除した項目の値は非表示になり、他の項目へ移されません。新しい表にはタイムをコピーしません。

50×14は従来のベスト・1HのAから基本4列を表示します。Aの変更時は基本4列を再計算し、追加列の入力は保持します。Brokenや追加メニューの値は直接入力し、「合計」などの自動計算は行いません。

Firestoreの共有ドキュメントには `rows` に加え `menus` を保存します。更新前に新しい `firestore.rules` を反映してください。一度menusを保存した後は、旧クライアントがmenusを欠落させる書き込みをルールで拒否します。管理者も更新後にページを再読み込みしてください。
